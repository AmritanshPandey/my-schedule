# Opportunity Decision Tree

**Lens:** Strategic Choice · **Method 21 of 21** · **Output:** `opportunity-output/21-opportunity-decision-tree.md`

**Question:** Should this opportunity be explored, validated, paused or rejected?

## Why it matters

Enthusiasm is not a decision. Four explicit tests, applied the same way every time, make the call defensible.

## Use when

- After synthesis, for the top 1–3 candidates.

## Needs

- Opportunity Map and method outputs
- Size range (from `opportunity-sizing`)
- Constraints
- Business profile (`opportunity-output/business-profile.md`)

## Steps

1. Test **demand** (evidence customers want it and will act), **fit** (with direction and capabilities), **advantage** (credible way to win, from VRIO or core competence), **feasibility** (can be built and delivered within constraints). Each: pass / weak / fail, with a one-line reason and evidence label.
2. Decide by pattern: **Validate** (passes demand and fit, at most one weak test: needs a specific test before committing), **Explore** (promising but evidence thin), **Pause** (fails a fixable test: name the trigger to revisit), **Reject** (fails demand or fit).
3. A failed test is never offset by strengths elsewhere without an explicit, written reason.
4. State the single piece of evidence that would move it to the next stage, and the next action to get it.
5. For Validate, prepare the handoff to `strategy-sprint`: the decision question, candidate options, map and ledger.

## Checks

- [ ] Tests answered from evidence.
- [ ] Decision follows the pattern.
- [ ] Failures not silently offset.
- [ ] Next action concrete.
- [ ] Material claims labeled per `references/evidence-rules.md`

## Output

- Test results
- Decision
- What would change it
- Next action and handoff
- **Signals for the map:** 1–3 candidate opportunities this supports or weakens, each with strength (strong / moderate / weak / assumed) and source IDs

## Reading the signal

This method makes the call; it does not add a new signal to the map.
