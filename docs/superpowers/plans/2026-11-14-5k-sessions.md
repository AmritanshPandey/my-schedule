# 5K Sessions Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A "Run a 5K" template that generates dated run Sessions, shows them on Today, logs runs three ways (mark done, typed, Apple Health), compares planned with actual, and proposes weekly adjustments the user approves.

**Architecture:** Three new synced collections (`sessions`, `sessionLogs`, `planAdjustments`) in `packages/core`, wired exactly like `setLogs`. All logic (generator, selectors, mutations, adjustment rules, Health matching) is pure functions in `packages/core/lib`, tested with `node:test`; the PWA (`components/`) and native app (`apps/native/src/components/`) render them and call the mutations through each shell's `setSchedule`.

**Tech Stack:** TypeScript, zod, Next.js 16 PWA, React Native 0.87 + NativeWind, `@lodev09/react-native-true-sheet`, `@kingstinct/react-native-healthkit` (new, iOS only), `node --test`.

**Spec:** `docs/superpowers/specs/2026-11-14-5k-sessions-design.md`

## Global Constraints

- Planned values are never overwritten by a log; logs live only in `sessionLogs`.
- An adjustment changes nothing until `decision: "accepted"`; rebuilds touch only sessions with `status: "planned"`, no log, no `editedAt`.
- Store metres and seconds; display km and min/km.
- Local-first: everything works offline; each new collection merges per id via `mergeKeyed(... byId(NS.x) ...)`.
- One Signal Rule (green only for completion/progress), Ink-First buttons, ≥44 px targets, WCAG 2.1 AA both themes, honour reduced motion, no em dashes in UI copy, no badges/confetti, no medical claims.
- Template copy includes: "This plan is general guidance. Listen to your body and ease off if something hurts."
- Same behaviour on PWA and iOS; Apple Health is iOS only.
- Precondition: other sessions' uncommitted edits to `scheduleTypes.ts`, `scheduleSchema.ts`, `scheduleMigrate.ts`, `mergeSchedule.ts`, `stampSchedule.ts` are committed or set aside before Task 1. Work on branch `feat/5k-sessions`. Never commit `AGENTS.md` or `.impeccable/critique/`.

## Review Focus

1. **Late-night runs and local dates:** a run finished at 23:40 matches that day's session; a Health workout's date is its local start date, never UTC. → test in Task 6.
2. **Bad setup inputs:** weeks < 4 or > 16, fewer than 3 or more than 5 run days, race date in the past, or target distance below current distance are rejected with a message, never generate a broken plan. → test in Task 3.
3. **Blank or zero log values:** distance or time of 0/blank cannot be saved as a typed log (no divide-by-zero pace); mark done still works. → test in Task 2.
4. **Re-importing Health:** the same workout seen on every foreground creates one log only (dedupe by `healthWorkoutId`), and a deleted manual log does not cause a duplicate. → test in Task 6.
5. **Deleting a plan mid-way:** future planned sessions vanish from Today; done sessions and their logs remain in history and never show as missed. → test in Task 2.

### Task 3: 5K plan generator

**Files:**
- Create: `packages/core/lib/runPlan.ts`, `lib/runPlan.ts` (re-export)
- Modify: `packages/core/lib/templates.ts` (remove the "Run Training" entry; export `RUN_5K_TEMPLATE_ID = "run-5k"`)
- Test: `tests/runPlan.test.mjs`

**Interfaces:**
- Consumes: Task 1 types, Task 2 `headline`.
- Produces:
  - `validateRunInputs(inputs: RunPlanInputs, todayISO: string): string | null`
  - `generateRunPlan(inputs: RunPlanInputs, adjustments: PlanAdjustment[], planId: string, nowISO: string): Session[]` (deterministic for the same inputs; ids from a seeded counter `${planId}-w${week}-s${slot}`)
  - `summarizeRunPlan(sessions: Session[]): { weeks: number; runsPerWeek: number; longRunFromKm: number; longRunToKm: number }`
  - `createRunPlan(schedule: Schedule, inputs: RunPlanInputs, opts: { createGoal: boolean; title?: string }, nowISO: string): { schedule: Schedule; planId: string }` (adds Plan with `category: "fitness"`, `generator`, optional Goal "Run <d> km" or "Run <d> km at <pace>/km", and sessions)
  - `rebuildRunPlan(schedule: Schedule, planId: string, todayISO: string, nowISO: string): Schedule` (regenerates from `plan.generator` + accepted adjustments; replaces only sessions dated ≥ today that are planned, unlogged, unedited)
  - `updateRunInputs(schedule: Schedule, planId: string, patch: Partial<Pick<RunPlanInputs, "runDays" | "startTime" | "targetPaceSecPerKm">>, todayISO: string, nowISO: string): Schedule` (bumps `inputsVersion`, then `rebuildRunPlan`; used by "Edit plan" in `PlanSessionsSection`)
- Generator rules (the numbers the tests pin):
  - Week 1 total = `currentDistanceKm × runDays.length × 0.9`, rounded to 0.5 km.
  - Each later week ≤ previous build week × 1.10 (+0.5 km rounding tolerance); every 4th week (4, 8, 12, 16) = 80% of week 3/7/11/15; final week = 70% of the week before.
  - Per week: one `"long"` run on the last chosen day (≈ 35% of the week, growing to `targetDistanceKm + 1` by the second-to-last week), one quality run on the second chosen day (`"intervals"` in the first half of the plan: 1 km easy + N × 400 m + 1 km easy with N from 4 to 8; `"tempo"` in the second half: 1 km easy + continuous tempo 1.5 → 3 km + 1 km easy), the rest `"easy"`.
  - Paces: easy = `easyPaceSecPerKm`; quality pace starts at `easy − 15` and moves linearly to the target pace (or `easy − 20` when no target) by the final quality run. Accepted `"pace"` adjustments add `detail.paceDeltaSec` to quality paces from their `weekIndex`.
  - Final run: last chosen day of the last week, `routineKey: "race"`, one distance task of `targetDistanceKm × 1000` at target pace.
  - Accepted `"repeat-week"` inserts a copy of week `weekIndex − 1` and shifts later weeks by 7 days; `"ease"` makes week `weekIndex` equal to week `weekIndex − 1`.
  - `estimatedMinutes` = Σ distance × pace (+ rests), rounded up to 5.
- [ ] **Step 1: Write failing tests**:
  - `validateRunInputs` rejects `weeks: 3` ("Choose 4 to 16 weeks."), `runDays` of 2 ("Pick 3 to 5 run days."), `targetDistanceKm < currentDistanceKm` ("Your target should be at least your current distance."), `startISO` before today ("Start today or later."). (Review Focus 2)
  - 8 weeks, 4 days (mon/wed/fri/sun), 3 km @ 360, target 5 km @ 330: 32 sessions; every `dateISO` is a chosen weekday ≥ `startISO`; weekly totals obey the 1.10 cap; week 4 total < week 3 total; week 8 total < week 7 total; last session `routineKey === "race"` with `distanceM === 5000` and pace 330; weeks 1–4 quality runs are `"intervals"`, weeks 5–7 `"tempo"`; quality pace never increases week to week.
  - Same inputs twice → deep-equal output.
  - `rebuildRunPlan` after accepting `{ kind: "pace", weekIndex: 3, detail: { paceDeltaSec: -10 } }` changes week ≥3 quality paces by −10 and leaves a logged week-3 session and an `editedAt` session byte-identical.
  - Accepted `"repeat-week"` at week 3 → 36 sessions, last date 7 days later.
  - `updateRunInputs` with `runDays` changed to tue/thu/sat/sun moves future untouched sessions onto those days and leaves past and logged ones in place.
- [ ] **Step 2: Run** `npm test` → FAIL.
- [ ] **Step 3: Implement** `packages/core/lib/runPlan.ts`.
